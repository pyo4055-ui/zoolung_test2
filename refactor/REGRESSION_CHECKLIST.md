# 주렁주렁 단체예약 / 현장스케줄 리팩토링 회귀검증 기준

## 원칙

- 현재 운영 `main`의 사용자 동작과 저장 결과가 정답이다.
- UI 문구, 업무 흐름, 계산 방식, DB collection/document/field 이름, localStorage key, 엑셀 양식을 임의 변경하지 않는다.
- 기존 파일은 새 구조의 동등성이 검증되기 전 삭제하지 않는다.
- 실 DB write 검증 전에는 PR을 Draft로 유지하고 `main`에 병합하지 않는다.

## 고객 예약

- 신규 단체 예약 신청
- 예약자명/연락처/이메일, 단체명/유형, 유료/인솔자 입력
- 무료 인솔자 및 유료 인솔자 계산
- 방문일, 입장/퇴장, 식사, 카페, 놀이터, 특이사항
- 당일 예약 차단, 예약 가능기간/마감/놀이터 중복 규칙
- 010 11자리 연락처 검증
- 동물원 안내와 놀이터 안내가 각각 현재 시점과 동일하게 표시
- 주차 안내 현재 동작 유지
- 예약 조회/변경/취소 및 상태 노출 유지

## 관리자 예약

- 관리자 보안 로그인/실패 잠금/세션 만료/로그아웃
- Firebase 직원 인증 전환
- 월 캘린더, 공휴일/주말, 수동/자동 마감
- 예약 확정/거절/취소/수정/빠른예약
- 접수일/예약일 기준 예약현황 조회

## 정산 / 아웃소싱

- 자체/업체 선택
- 실제 유료/무료인솔/유료인솔/카페금액 입력
- 업체별 단체가, 매표/카페 수수료 및 기존 정산 재계산 규칙
- 정산완료 표시와 업체별 KPI

## 엑셀 4종 — 각각 별도 양식 유지

1. 예약현황: 접수일/예약일/단체/상태/실인원/매표/카페 등 현재 열 순서 및 표시
2. 식사관리: 날짜/식사시간/단체/메뉴/수량/금액/특이사항, 병합/합계 유지
3. 아웃소싱: 업체별 입장/매출/수수료/합계 및 헤더 규칙 유지
4. 스케줄관리: 단체별 시간표/컨텐츠 구조와 현재 양식 유지

## 관리자 스케줄

- 확정 예약 날짜별 조회
- 4F/5F/식사/놀이터/추가 컨텐츠
- 시작/종료, 겹침, 종료<=시작, 퇴장시간 초과 차단
- 스케줄 반영 -> `scheduleGroups`
- 스케줄 확정 -> 원본 예약 `schedulePublished` + `customerSchedule`
- 확정취소 시 고객 노출 해제
- 고객 확정스케줄/확대 보기 유지

## 현장 스케줄

- 날짜 이동/새로고침/실시간 연동
- 예약/실제 인원 KPI, 단체 카드, 전화번호, 타임라인, 커스텀 컨텐츠/색상/범례
- 실제 유료/인솔, 도착/퇴장예정, 결제, 컬러북, 메모, 인상착의, 당일취소, 식사위치, 카페내용
- 컨텐츠 기존/변경 비교 및 시간 저장
- 현장에서 임의로 수정한 스케줄은 원본 예약에 역반영하지 않음
- 공용 메모는 수정 잠금과 관계없이 수정 가능

## 데이터 계약

- localStorage: `zr_bookings` 유지
- Firestore: `reservations`, `reservationAvailability`, `scheduleGroups`, `scheduleSharedMemos` 유지
- 예약 ID 및 기존 필드명 보존
- 기존 예약을 불러온 뒤 저장하지 않아도 필드가 손실/초기화되지 않아야 함
- 관리자/고객/현장 실시간 listener 중복 정리 시 UI 결과가 동일해야 함

## 병합 전 실제 DB 검증

- 신규 예약 작성 -> Firestore 확인 -> 다른 세션/화면 조회
- 관리자 예약 수정/확정/취소 -> Firestore와 고객 화면 확인
- 정산 저장 -> 재조회 후 계산값 동일 확인
- 스케줄 반영/확정 -> `scheduleGroups` + 고객 공개 확인
- 현장 정보 수정 -> 새로고침/다른 세션에서 동일 확인
- 현장 수정 후 원본 `reservations` 예약 필드가 원치 않게 변경되지 않았는지 확인
- 공용 메모 저장 -> 다른 세션 실시간 확인
- 엑셀 4종을 정리 전/후 내려받아 열/병합/합계/값 비교
